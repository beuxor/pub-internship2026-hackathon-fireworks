# 要件定義：パーセントバルーン（EC購買データ版）

## 1. 概要

楽天EC購買データ（約147万件）から自動生成した「割合(%)」の問題に対し、プレイヤーが予想値を入力し、正解との誤差の小ささを競うゲーム。
持ち点100から各問の誤差を引いていき、5問終了時の残り持ち点が最終得点となる。

## 3. ゲームルール

### 3.1 基本ルール

| 項目 | 内容 |
|---|---|
| 初期持ち点 | 100 |
| 問題数 | 5問 |
| 減点 | 各問 `|予想値 - 正解値|` を持ち点から減算（小数第1位で四捨五入した整数値） |
| 最終得点 | 5問終了時の残り持ち点（0未満にはならない。0の場合は0として記録） |
| ゲームオーバー | 5問終了前に持ち点が0以下になった時点で即終了 |
| 入力範囲 | 0〜100の整数（範囲外は入力不可。未入力で制限時間切れの場合は誤差50として扱う） |
| DAMAGE_RATE | 1.0（減点 = `ROUND(|予想値 - 正解値| × DAMAGE_RATE)`）。テストプレイ後に0.7〜1.0で調整可能 |

### 3.2 勝敗判定（2人対戦）

以下の順に判定する。上位の条件で決着した場合、下位は評価しない。

1. 両者が5問完走した場合 → 残り持ち点が多いほうが勝ち
2. 片方のみ完走した場合 → 完走したほうが勝ち
3. 両者ゲームオーバーの場合 → 到達問題数（ゲームオーバーになった問題を含む）が多いほうが勝ち
4. 到達問題数も同じ場合 → 引き分け
5. 残り持ち点が同点の場合 → 引き分け

引き分けの場合、両プレイヤーに「引き分け」と表示する。再戦は促すが強制しない。

## 4. モード

優先度の高い順に実装する。デプロイ時間切れでも成立する状態を早期に確保する。

### 4.1 ソロモード（優先度：最高 — 必須）

- 1人で5問に挑戦し、最終得点を記録する
- ゲーム開始時に問題プールからランダムに5問を選択する。同一ゲーム内で同じ問題は出さない
- 終了後、プレイヤー名（任意入力、最大20文字）と得点をリーダーボードに登録する
- リーダーボードは得点の降順で上位20件を表示する。同点の場合は登録日時が早いほうを上位とする
- 通信を伴わないため、これ単体で完成品として成立する

### 4.2 ローカル対戦（優先度：中）

- 1台の端末を2人で共有する
- ゲーム開始時に両プレイヤーの名前を入力する（最大20文字、重複不可）
- 各問の流れ:
  1. プレイヤー1の入力画面を表示。入力欄はパスワード入力風にマスク表示する
  2. プレイヤー1が回答を送信後、「端末をプレイヤー2に渡してください」の交代画面を表示する
  3. プレイヤー2が「準備OK」ボタンを押すとプレイヤー2の入力画面を表示する
  4. プレイヤー2が回答を送信後、正解値と双方の誤差・減点・残り持ち点を同時に開示する
- 制限時間は設けない
- どちらかがゲームオーバーになった場合、残りのプレイヤーのみ続行する
- 通信を伴わないため、オンラインが間に合わなくても対戦体験を提供できる

### 4.3 オンライン対戦（優先度：低 — 時間切れなら実装しない）

- ホストが部屋を作成し、4桁の数字の合言葉（ランダム生成、0000〜9999）を相手に共有する
- ゲストが合言葉を入力して入室する。合言葉が存在しない場合はエラーを表示する
- 両者が入室した時点でゲームが自動開始される
- 各問の制限時間は15秒。制限時間内に回答しなかった場合は誤差50として扱う
- 両者の回答が揃った時点（または制限時間経過時点）で結果を開示する
- 状態同期は2秒間隔のポーリングで行う
- 相手の離脱（30秒間ポーリングなし）を検知した場合、残ったプレイヤーの勝ちとする
- 合言葉の有効期限は作成から10分間。10分以内にゲストが入室しなかった場合は部屋を無効化する

## 5. 問題プール

### 5.1 生成方針

事前にバッチで生成し、テーブルに保持する。リアルタイム生成は行わない。
生成件数は200問を目標とする（5問×複数回プレイに十分な量を確保）。

### 5.2 データ調査結果

ソーステーブル `team_f_db.development.rakuten_purchase_mart_v2` の調査結果:

- 総レコード数: 1,468,432件
- 主要カラム: GENDER_NAME(3値), AGE_CATEGORY(8値), STATE_NAME(48値), REGION(9値), CATEGORY_LEVEL_1(38値), CATEGORY_LEVEL_2(449値), MARRIAGE_STATUS(4値), OCCUPATION_NAME(31値), SALE_FLAG, IS_PRIME_CUSTOMER

### 5.3 問題の型と候補数

以下の条件で調査: 正解値が5%以上95%以下、母集団1,000件以上。

| 型 | 例 | 候補数 | 正解値範囲 |
|---|---|---|---|
| 属性×カテゴリ | 30代女性の購入のうち、食品が占める割合 | 114問 | 5〜19% |
| 性別構成 | 家電カテゴリの購入者のうち、男性が占める割合 | 38問 | 12〜68% |
| 年代構成 | 食品カテゴリの購入者のうち、40代が占める割合 | 155問 | 5〜60% |
| 職業×カテゴリ | 会社員の購入のうち、家電が占める割合 | 213問 | 5〜24% |
| 地域×カテゴリ | 関東地方の購入のうち、食品が占める割合 | 59問 | 5〜13% |
| 婚姻状況×カテゴリ | 既婚者の購入のうち、食品が占める割合 | 27問 | 5〜14% |
| プライム会員 | 家電の購入者のうち、プライム会員が占める割合 | 38問 | 19〜56% |
| **合計** | | **644問** | **5〜68%** |

**注意:**
- セール品型（地域×セール品の割合）はSALE_FLAGが全体の2.1%しかなく、5%の下限を満たせないため不採用
- 正解値の分布は5〜20%帯に偏る傾向がある。性別構成(12-68%)・年代構成(5-60%)・プライム会員(19-56%)を積極的に混ぜてバランスを取る

### 5.4 採用条件

- 正解値が5%以上95%以下であること
- 母集団のレコード数が1,000件以上であること
- 同一の母集団・分子の組み合わせから重複する問題を出さないこと
- 200問を選出する際、正解値が10%刻みの各バケットから均等に近い数を採用する（極端な偏り防止）
- 出題時は同じ問題型が3問以上連続しないようシャッフルする

### 5.5 テーブルスキーマ

```sql
QUESTION_POOL (
  QUESTION_ID      NUMBER        -- 主キー（1から連番）
  QUESTION_TYPE    VARCHAR(50)   -- 問題の型（ATTRIBUTE_CATEGORY / GENDER_COMPOSITION / AGE_COMPOSITION / OCCUPATION_CATEGORY / REGION_CATEGORY / MARRIAGE_CATEGORY / PRIME_MEMBER）
  QUESTION_TEXT    VARCHAR(500)  -- 表示する問題文（日本語）
  ANSWER_PCT       NUMBER(5,2)   -- 正解の割合（小数第2位まで）
  DENOMINATOR_CNT  NUMBER        -- 母集団の件数
  NUMERATOR_CNT    NUMBER        -- 分子の件数
)
```

## 6. データ設計（ゲーム状態）

### 6.1 GAME_SESSION

ゲームのセッション管理。ソロ・ローカル対戦はセッション不要（クライアント側で状態管理）。
オンライン対戦のみサーバー側で状態を持つ。

```sql
GAME_SESSION (
  SESSION_ID     VARCHAR(36)     -- UUID
  ROOM_CODE      VARCHAR(4)      -- 4桁の合言葉（オンラインのみ）
  MODE           VARCHAR(10)     -- SOLO / LOCAL / ONLINE
  STATUS         VARCHAR(10)     -- WAITING / PLAYING / FINISHED
  PLAYER1_NAME   VARCHAR(20)     -- プレイヤー1の名前
  PLAYER2_NAME   VARCHAR(20)     -- プレイヤー2の名前（対戦時のみ）
  QUESTION_IDS   VARCHAR(100)    -- カンマ区切りの問題ID（例: "3,15,42,7,88"）
  CREATED_AT     TIMESTAMP_NTZ
  UPDATED_AT     TIMESTAMP_NTZ
)
```

### 6.2 GAME_ANSWER

各問の回答記録。オンライン対戦時のポーリングと結果表示に使用。

```sql
GAME_ANSWER (
  ANSWER_ID      NUMBER          -- 主キー（連番）
  SESSION_ID     VARCHAR(36)     -- GAME_SESSION.SESSION_ID
  PLAYER_NAME    VARCHAR(20)     -- 回答したプレイヤーの名前
  QUESTION_NO    NUMBER          -- 何問目か（1〜5）
  QUESTION_ID    NUMBER          -- QUESTION_POOL.QUESTION_ID
  ANSWER_PCT     NUMBER(5,2)     -- 回答値
  ERROR_ABS      NUMBER(5,2)     -- |回答値 - 正解値|
  DAMAGE         NUMBER          -- 実際の減点（ROUND(ERROR_ABS * DAMAGE_RATE)）
  REMAINING_HP   NUMBER          -- 回答後の残り持ち点
  CREATED_AT     TIMESTAMP_NTZ
)
```

### 6.3 LEADERBOARD

```sql
LEADERBOARD (
  LEADERBOARD_ID  NUMBER          -- 主キー（連番）
  PLAYER_NAME     VARCHAR(20)     -- プレイヤー名
  MODE            VARCHAR(10)     -- SOLO / LOCAL / ONLINE
  SCORE           NUMBER          -- 最終持ち点（0〜100）
  QUESTIONS_CLEARED NUMBER        -- 完走した問題数（0〜5）
  CREATED_AT      TIMESTAMP_NTZ
)
```

## 7. 画面一覧

### 7.1 トップ画面

- モード選択ボタン: ソロ / ローカル対戦 / オンライン対戦
- リーダーボード表示（上位20件。プレイヤー名、得点、日時）
- 未実装モードのボタンはグレーアウトし「Coming Soon」と表示

### 7.2 ゲーム準備画面

- **ソロ**: プレイヤー名入力 → 「ゲーム開始」ボタン
- **ローカル対戦**: プレイヤー1・2の名前入力 → 「ゲーム開始」ボタン
- **オンライン対戦（ホスト）**: プレイヤー名入力 → 「部屋を作成」ボタン → 合言葉表示 + 待機
- **オンライン対戦（ゲスト）**: プレイヤー名入力 + 合言葉入力 → 「入室」ボタン

### 7.3 出題・回答画面

- 問題文を表示
- 現在の持ち点をゲージ（プログレスバー）で表示
- 「第N問 / 全5問」を表示
- 回答入力欄（0〜100のスライダーまたは数値入力）
- 「回答する」ボタン
- ローカル対戦時: 入力値をマスク表示（`***`）。どちらのプレイヤーのターンか明示

### 7.4 交代画面（ローカル対戦のみ）

- 「端末を[プレイヤー2名]に渡してください」のメッセージ
- 「準備OK」ボタン（これを押すまで次の入力画面に遷移しない）

### 7.5 問題結果画面

- 正解値を大きく表示
- 各プレイヤーの回答値、誤差、減点、更新後の持ち点を表示
- 対戦時は2人分を左右に並べて表示
- 「次の問題へ」ボタン（最終問は「結果を見る」ボタン）

### 7.6 ゲーム終了画面

- 最終得点を表示
- 対戦時は勝敗（勝ち/負け/引き分け）を表示
- ソロ時はリーダーボードへの登録確認
- 「もう一度遊ぶ」「トップに戻る」ボタン
