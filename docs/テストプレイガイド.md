# テストプレイガイド

## 1. 環境準備

### 1.1 前提

- Node.js 20 以上がインストールされていること
- 問題データ `public/questions.json` が存在すること（655問分のJSONファイル）

### 1.2 起動手順

```bash
cd /workspaces/pub-internship2026-hackathon-fireworks
npm install
npm run dev
```

ブラウザで `http://localhost:3000` にアクセスする。

### 1.3 データ構成

- **問題データ**: `public/questions.json`（起動時にメモリにキャッシュ。655問収録）
- **リーダーボード**: `.leaderboard.json`（プロジェクトルートに自動生成）
- **オンラインセッション**: `.sessions.json` / `.answers.json`（プロジェクトルートに自動生成）

問題データを再生成したい場合:
```bash
snow sql -q "USE WAREHOUSE team_f_wh; SELECT QUESTION_ID, QUESTION_TYPE, QUESTION_TEXT, ANSWER_PCT FROM team_f_db.development.question_pool" --connection dev --format json | python3 -c "import json,sys; d=json.load(sys.stdin); d=d[-1] if isinstance(d[0],list) else d; open('public/questions.json','w').write(json.dumps(d,ensure_ascii=False))"
```

## 2. ソロモードのテスト

### 2.1 正常系

1. トップ画面で「ひとり用」を選択
2. プレイヤー名に「テスト太郎」と入力し「ゲーム開始」
3. 以下を5問分繰り返す:
   - 問題文が表示され、「第N問」のラベルが正しいこと
   - 残り風船が100から始まること
   - 0〜100の整数を入力し「回答する」ボタンを押す
   - 結果画面に正解値、自分の回答、誤差、減点、残り持ち点が表示されること
   - 「次の問題へ」ボタンで次の問題に遷移すること
4. 5問終了後、ゲーム終了画面が表示されること
5. 「スコアを登録」ボタンでリーダーボードに保存できること
6. 「トップへ」で戻り、リーダーボードに記録が表示されること

### 2.2 ゲームオーバーのテスト

1. 意図的に大きく外れた回答を入力する（正解が30%なら90%と入力するなど）
2. 持ち点が0以下になった時点で即座にゲームオーバーとなり、以降の問題は表示されないこと
3. ゲーム終了画面に「ゲームオーバー」と表示されること

### 2.3 入力バリデーション

- 名前が空の状態で「ゲーム開始」→ エラーメッセージが表示されること
- 回答欄に文字列や101以上の数値を入れてもボタンが押せないこと

## 3. ローカル対戦のテスト

### 3.1 正常フロー

1. トップ画面で「ふたり用（ローカル）」を選択
2. プレイヤー1に「Alice」、プレイヤー2に「Bob」と入力
3. 各問の流れ:
   - Aliceの名前が表示された入力画面になること
   - 入力欄がパスワードマスク（`***`）で相手に見えないこと
   - 回答送信後、「端末をBobに渡してください」の交代画面になること
   - 「準備OK」を押すとBobの入力画面になること
   - Bob回答後、正解・双方の結果が並んで表示されること
4. 5問終了後、勝敗が正しく判定されること

### 3.2 勝敗判定の確認ポイント

| シナリオ | 期待される結果 |
|---|---|
| 両者完走、Alice: 残り60点、Bob: 残り45点 | Aliceの勝ち |
| Aliceがゲームオーバー、Bobが完走 | Bobの勝ち |
| 両者ゲームオーバー、到達問題数が同じ | 引き分け |
| 同点完走 | 引き分け |

### 3.3 片方ゲームオーバー

- 片方がゲームオーバーになった場合、もう片方のみが続行すること
- 交代画面はスキップされ、残ったプレイヤーだけが出題されること

## 4. オンライン対戦のテスト

### 4.1 準備

2つのブラウザタブ（またはシークレットモードの別ウィンドウ）を使う。

### 4.2 正常フロー

1. タブ1: 「ふたり用（オンライン）」→ 名前入力 → 「部屋を作る」
2. 4桁の合言葉が表示されること
3. タブ2: 「ふたり用（オンライン）」→ 名前入力 → 合言葉を入力 → 「入室」
4. 両方のタブでゲームが開始されること
5. 各問:
   - 制限時間15秒のカウントダウンが表示されること
   - 両者の回答が揃うと結果が表示されること
   - 結果画面に自分と相手の回答・減点が並んで表示されること
6. 5問終了後、勝敗が表示されること

### 4.3 制限時間切れのテスト

- 15秒間回答しないと自動的に回答が送信されること
- 制限時間切れ時の減点は誤差50相当となること

### 4.4 部屋の有効期限

- 部屋を作成して10分以上経過後に合言葉で入室を試みると「部屋が見つかりません」になること

## 5. リーダーボードのテスト

1. 複数回プレイしてスコアを登録する
2. トップ画面のリーダーボードにスコアが降順で表示されること
3. 上位20件まで表示されること
4. 同点の場合は登録日時が早いほうが上位であること

## 6. DAMAGE_RATE の調整

テストプレイの結果を踏まえて、ゲームバランスを調整する。

### 6.1 確認項目

- 平均的なプレイヤーが5問完走できるか
- 誤差20程度の回答が続くと3問目あたりでゲームオーバーになるか（DAMAGE_RATE=1.0の場合）
- ゲームが簡単すぎる場合: DAMAGE_RATE はそのまま（1.0）
- ゲームが難しすぎる場合: DAMAGE_RATE を 0.8 や 0.7 に下げる

### 6.2 変更方法

`lib/constants.ts` の `DAMAGE_RATE` の値を変更する:

```typescript
export const DAMAGE_RATE = 0.8  // 1.0 → 0.8 に変更
```

## 8. デプロイ手順

```bash
# マニフェスト生成（初回のみ）
snow app setup --app-name="percent_balloon"

# デプロイ
snow app deploy --verbose
```

デプロイ成功後、出力されるURLでアクセスできることを確認する。

注意: デプロイ時にはAPIルートのSnowflake接続方式を、`lib/snowflake-cli.ts`（開発用CLIプロキシ）から`lib/snowflake.ts`（本番用SDK直結）に切り替えること。SPCS環境ではOAuth認証が自動的にトークンファイル経由で処理されるため、ブラウザ認証の問題は発生しない。
